1. ตารางทั้งหมด 8 ตาราง (ข้อ 2.1)

ตาราง เก็บอะไร ความสัมพันธ์ (ข้อ 2.2)

periods รอบการประเมิน + วันเริ่ม/สิ้นสุด 1 รอบ มีหลายหัวข้อ, หลายการมอบหมาย

2. Data Dictionary — ชนิดข้อมูล (ข้อ 2.3)

ข้อมูล ชนิดที่เลือก เหตุผล
รหัส (id) INT AUTO_INCREMENT PRIMARY KEY เลขเรียงอัตโนมัติ ไม่ซ้ำ
ชื่อผู้ใช้ VARCHAR(50) UNIQUE ข้อความสั้น ห้ามซ้ำ
รหัสผ่าน VARCHAR(255) เก็บแบบเข้ารหัส bcrypt (ยาว 60 ตัว)
บทบาท / สถานะ / รูปแบบคะแนน ENUM(...) มีค่าได้ไม่กี่แบบ ป้องกันพิมพ์ผิด
วันที่เริ่ม / สิ้นสุด DATE เก็บเฉพาะวันที่
รายละเอียด / ความเห็น TEXT ข้อความยาว
น้ำหนักคะแนน DECIMAL(6,2) ทศนิยม 2 ตำแหน่ง แม่นยำ
คะแนน INT 0–1 หรือ 1–4
ต้องเปลี่ยนรหัส BOOLEAN จริง / เท็จ
ชื่อไฟล์ VARCHAR(255) เก็บชื่อไฟล์ ตัวไฟล์อยู่ในโฟลเดอร์ uploads

3. การตั้งชื่อ (Naming Conventions ข้อ 2.5)

  • ชื่อตาราง: ภาษาอังกฤษ ตัวเล็ก พหูพจน์ คั่นด้วย _ เช่น self_scores
  • ชื่อฟิลด์: ตัวเล็ก snake_case เช่น full_name, start_date
  • Primary Key ชื่อ id ทุกตาราง
  • Foreign Key ชื่อ <ชื่อตารางแม่เอกพจน์>_id เช่น period_id, indicator_id (ยกเว้น evaluatee_id, evaluator_id ที่บอกบทบาทของ user)
  • ชื่อคลาสใน Class Diagram: เอกพจน์ ตัวแรกพิมพ์ใหญ่ PascalCase เช่น SelfDetail, คุณสมบัติแบบ camelCase เช่น fullName

4. Class Diagram (ข้อ 2.4)

ส่วนประกอบของ 1 คลาส (ใน Draw.io ใช้แถบซ้าย UML → Class)

┌───────────────────────┐
│ ชื่อคลาส (User)        │ ← ช่องบน
├───────────────────────┤
│ - id : int            │ ← คุณสมบัติ (attribute)  "-" = private
│ - username : string   │
├───────────────────────┤
│ + login() : token     │ ← เมธอด (method)  "+" = public
└───────────────────────┘

ความสัมพันธ์: ลากเส้นจากคลาสแม่ไปคลาสลูก แล้วพิมพ์ 1 ที่ฝั่งแม่ และ * ที่ฝั่งลูก (หมายถึง หนึ่งต่อหลาย)

ความสัมพันธ์ อ่านว่า
Period 1 — * Topic 1 รอบ มีได้หลายหัวข้อ
Topic 1 — * Indicator 1 หัวข้อ มีได้หลายตัวชี้วัด
User 1 — * Assignment ผู้ใช้ 1 คน ถูกมอบหมาย/ถูกประเมินได้หลายครั้ง (2 เส้น: evaluatee, evaluator)
Assignment 1 — * Score การประเมิน 1 ครั้ง มีคะแนนหลายตัวชี้วัด
Indicator 1 — * SelfDetail ตัวชี้วัด 1 ข้อ มีรายละเอียดหลายรายการ

เมธอดในคลาสตรงกับ API จริง เช่น Assignment.saveDraft() = PUT /api/evaluate/:id, Assignment.confirm() = PUT /api/evaluate/:id/confirm ถ้ากรรมการถามให้ชี้ได้ว่าเมธอดไหนอยู่ไฟล์ไหน

05 ส่วนที่ 4 การออกแบบ RESTful API — 5 คะแนน

ผู้รับผิดชอบ: คนที่ 3 เขียนเอกสาร docs/API.md (คัดลอกจากเฉลยแล้วปรับได้) · คนที่ 1 ทำ API ให้ตรงเอกสาร

1. หลัก RESTful (ข้อ 4.1–4.2)

Method ใช้ทำ ตัวอย่าง
GET อ่านข้อมูล GET /api/users, GET /api/users/5
POST เพิ่มข้อมูลใหม่ POST /api/users
PUT แก้ไขข้อมูล PUT /api/users/5
DELETE ลบข้อมูล DELETE /api/users/5

ชื่อ Endpoint เป็น คำนามพหูพจน์ (/users, /periods, /indicators) และใช้ /:id ระบุตัวที่ต้องการ ไม่ใส่คำกริยาใน URL (ยกเว้นงานพิเศษเช่น /login, /confirm, /reset-password)

2. รูปแบบ Response เดียวกันทุก API (ข้อ 4.3, 6.8)

{ "status": "success", "message": "เพิ่มผู้ใช้แล้ว", "data": { "id": 6 } }
{ "status": "error", "message": "ไม่พบผู้ใช้", "data": null }
Status Code ใช้เมื่อ (ข้อ 4.4)
200 OK สำเร็จ
400 Bad Request ข้อมูลไม่ครบ / ผิดรูปแบบ / ซ้ำ
401 Unauthorized ไม่มี token หรือ token ผิด / รหัสผ่านผิด
403 Forbidden login แล้วแต่ไม่มีสิทธิ์ (เช่น ผู้รับเรียก API ของ admin)
404 Not Found ไม่พบข้อมูล หรือไม่มี API นี้
500 Internal Server Error โค้ดพัง / ฐานข้อมูลมีปัญหา

3. ความปลอดภัย (ข้อ 4.5, 6.12)

  1. Login สำเร็จ → server สร้าง JWT ที่ลงนามด้วย JWT_SECRET อายุ 8 ชั่วโมง
  2. หน้าเว็บเก็บ token ใน localStorage และแนบทุกครั้ง Authorization: Bearer <token>
  3. middleware login ตรวจ token → ไม่ผ่าน = 401
  4. middleware allow('admin') ตรวจบทบาท → ไม่ตรง = 403
  5. รหัสผ่านเก็บแบบ bcrypt hash ไม่เก็บตัวจริง
  6. SQL ใช้ ? (prepared statement) ป้องกัน SQL Injection

4. รายการ API ทั้งหมด

ดูเอกสารเต็มในไฟล์ docs/API.md ของเฉลย (มีตารางทุก Endpoint พร้อม parameter และตัวอย่าง 6.1–6.4 แบบละเอียด) สรุปกลุ่มได้ดังนี้

กลุ่ม Path หลัก สิทธิ์
เข้าสู่ระบบ / ข้อมูลส่วนตัว /api/auth ทุกคน
ผู้ใช้ /api/users admin
รอบ หัวข้อ ตัวชี้วัด /api/periods, /api/topics, /api/indicators admin
มอบหมายกรรมการ /api/assignments admin
ประเมินตนเอง /api/self evaluatee
ให้คะแนน /api/evaluate evaluator
รายงาน /api/reports ตามสิทธิ์
ไฟล์ /api/files login
สำรองข้อมูล /api/backup admin

ในเอกสาร ต้องระบุ parameter ว่ามาจากไหน (ข้อ 6.10)

  • path เช่น /users/:id → req.params.id
  • query เช่น /users?role=evaluator → req.query.role
  • body (JSON) → req.body.full_name
  • form-data (อัปโหลดไฟล์) → req.file

1.5 backend/schema.sql — สร้าง 8 ตาราง

ไฟล์ backend/schema.sql

-- ฐานข้อมูลระบบประเมินบุคลากร 8 ตาราง
-- อ่านจากบนลงล่าง: ตารางลูกอ้างถึงตารางแม่ด้วย FOREIGN KEY

-- 1) ผู้ใช้ทุกคน แยกด้วย role
CREATE TABLE IF NOT EXISTS users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  full_name VARCHAR(100) NOT NULL,
  email VARCHAR(100) NOT NULL DEFAULT '',
  department VARCHAR(100) NOT NULL DEFAULT '',
  role ENUM('admin','evaluatee','evaluator') NOT NULL,
  must_change_password BOOLEAN NOT NULL DEFAULT TRUE
);

-- 2) รอบการประเมิน มีวันเปิด-ปิด
CREATE TABLE IF NOT EXISTS periods (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL
);

-- 3) หัวข้อการประเมิน อยู่ในรอบ
CREATE TABLE IF NOT EXISTS topics (
  id INT AUTO_INCREMENT PRIMARY KEY,
  period_id INT NOT NULL,
  name VARCHAR(150) NOT NULL,
  FOREIGN KEY (period_id) REFERENCES periods(id) ON DELETE CASCADE
);

-- 4) ตัวชี้วัด อยู่ในหัวข้อ
--    score_type: yesno = มี/ไม่มี (0-1), scale = ระดับ 1-4
CREATE TABLE IF NOT EXISTS indicators (
  id INT AUTO_INCREMENT PRIMARY KEY,
  topic_id INT NOT NULL,
  name VARCHAR(150) NOT NULL,
  detail TEXT,
  weight DECIMAL(6,2) NOT NULL DEFAULT 1,
  score_type ENUM('yesno','scale') NOT NULL DEFAULT 'scale',
  evidence VARCHAR(255) NOT NULL DEFAULT '',
  FOREIGN KEY (topic_id) REFERENCES topics(id) ON DELETE CASCADE
);

-- 5) การมอบหมายกรรมการ 1 แถว = กรรมการ 1 คน ประเมินผู้รับ 1 คน ในรอบ 1 รอบ
--    status: pending = ยังไม่ประเมิน, draft = บันทึกร่าง, confirmed = ยืนยันผลแล้ว
CREATE TABLE IF NOT EXISTS assignments (
  id INT AUTO_INCREMENT PRIMARY KEY,
  period_id INT NOT NULL,
  evaluatee_id INT NOT NULL,
  evaluator_id INT NOT NULL,
  committee_role ENUM('chair','member') NOT NULL DEFAULT 'member',
  status ENUM('pending','draft','confirmed') NOT NULL DEFAULT 'pending',
  comment TEXT,
  signature VARCHAR(255),
  UNIQUE (period_id, evaluatee_id, evaluator_id),
  FOREIGN KEY (period_id) REFERENCES periods(id) ON DELETE CASCADE,
  FOREIGN KEY (evaluatee_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (evaluator_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 6) คะแนนที่ผู้รับประเมินตนเอง (ตัวชี้วัดละ 1 คะแนน)
CREATE TABLE IF NOT EXISTS self_scores (
  id INT AUTO_INCREMENT PRIMARY KEY,
  evaluatee_id INT NOT NULL,
  indicator_id INT NOT NULL,
  score INT NOT NULL,
  UNIQUE (evaluatee_id, indicator_id),
  FOREIGN KEY (evaluatee_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (indicator_id) REFERENCES indicators(id) ON DELETE CASCADE
);

-- 7) รายละเอียดและหลักฐานของผู้รับ (ตัวชี้วัดละกี่รายการก็ได้)
CREATE TABLE IF NOT EXISTS self_details (
  id INT AUTO_INCREMENT PRIMARY KEY,
  evaluatee_id INT NOT NULL,
  indicator_id INT NOT NULL,
  detail TEXT NOT NULL,
  url VARCHAR(500) NOT NULL DEFAULT '',
  file_name VARCHAR(255) NOT NULL DEFAULT '',
  FOREIGN KEY (evaluatee_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (indicator_id) REFERENCES indicators(id) ON DELETE CASCADE
);

-- 8) คะแนนที่กรรมการให้ (ตัวชี้วัดละ 1 คะแนน ต่อการมอบหมาย 1 แถว)
CREATE TABLE IF NOT EXISTS scores (
  id INT AUTO_INCREMENT PRIMARY KEY,
  assignment_id INT NOT NULL,
  indicator_id INT NOT NULL,
  score INT NOT NULL,
  UNIQUE (assignment_id, indicator_id),
  FOREIGN KEY (assignment_id) REFERENCES assignments(id) ON DELETE CASCADE,
  FOREIGN KEY (indicator_id) REFERENCES indicators(id) ON DELETE CASCADE
);
  • ON DELETE CASCADE = ลบแม่แล้วลูกหายตาม เช่น ลบรอบ → หัวข้อ ตัวชี้วัด การมอบหมาย หายด้วย
  • UNIQUE (assignment_id, indicator_id) = กรรมการ 1 คนให้คะแนนตัวชี้วัดละครั้งเดียว (ใช้คู่กับ ON DUPLICATE KEY UPDATE เพื่อแก้ไข)

// ฟังก์ชันช่วยที่ใช้ซ้ำหลายไฟล์
const { query } = require('./db');

// ตอบกลับเมื่อสำเร็จ: { status, message, data }
function ok(res, data = null, message = 'สำเร็จ') {
  res.json({ status: 'success', message, data });
}

// ตอบกลับเมื่อผิดพลาด เช่น error(res, 404, 'ไม่พบข้อมูล')
function error(res, code, message) {
  res.status(code).json({ status: 'error', message, data: null });
}

// วันนี้อยู่ในช่วงเปิดประเมินของรอบหรือไม่
function isOpen(period) {
  const today = new Date().toLocaleDateString('sv-SE'); // รูปแบบ 2026-10-26
  return today >= period.start_date && today <= period.end_date;
}

// คะแนนถูกชนิดหรือไม่: มี/ไม่มี = 0,1  สเกล = 1-4
function validScore(indicator, score) {
  if (indicator.score_type === 'yesno') return score === 0 || score === 1;
  return [1, 2, 3, 4].includes(score);
}

// คิดคะแนนร้อยละแบบถ่วงน้ำหนัก ถ้ายังให้คะแนนไม่ครบทุกตัวชี้วัด คืนค่า null
function percent(indicators, scores) {
  if (indicators.length === 0) return null;
  let total = 0;
  let totalWeight = 0;
  for (const item of indicators) {
    const row = scores.find((s) => s.indicator_id === item.id);
    if (!row) return null;
    const max = item.score_type === 'yesno' ? 1 : 4;
    total += (row.score / max) * Number(item.weight);
    totalWeight += Number(item.weight);
  }
  return Math.round((total / totalWeight) * 10000) / 100;
}

// ตัวชี้วัดทั้งหมดของรอบ (พร้อมชื่อหัวข้อ)
function getIndicators(periodId) {
  return query(
    `SELECT i.*, t.name AS topic_name FROM indicators i
     JOIN topics t ON t.id = i.topic_id
     WHERE t.period_id = ? ORDER BY t.id, i.id`,
    [periodId],
  );
}

// หารอบของตัวชี้วัด (ใช้ตรวจว่ารอบเปิดอยู่หรือไม่)
async function getPeriodOfIndicator(indicatorId) {
  const rows = await query(
    `SELECT p.* FROM periods p
     JOIN topics t ON t.period_id = p.id
     JOIN indicators i ON i.topic_id = t.id
     WHERE i.id = ?`,
    [indicatorId],
  );
  return rows[0];
}

module.exports = { ok, error, isOpen, validScore, percent, getIndicators, getPeriodOfIndicator };

ตัวอย่างการคิด percent() — ตัวชี้วัด A น้ำหนัก 60 แบบสเกล ได้ 3 · ตัวชี้วัด B น้ำหนัก 40 แบบมี/ไม่มี ได้ 1

A = 3/4 × 60 = 45
B = 1/1 × 40 = 40
รวม = (45 + 40) / (60 + 40) × 100 = 85%

2.2 backend/auth.js — JWT และตรวจสิทธิ์

ไฟล์ backend/auth.js

// ตรวจ JWT Token และสิทธิ์ตามบทบาท
const jwt = require('jsonwebtoken');
const { error } = require('./helpers');

const SECRET = process.env.JWT_SECRET || 'change-this-secret-key';

// สร้าง token (ลงนามด้วย SECRET) อายุ 8 ชั่วโมง
function createToken(user) {
  return jwt.sign(
    { id: user.id, role: user.role, must_change_password: !!user.must_change_password },
    SECRET,
    { expiresIn: '8h' },
  );
}

// middleware: ต้อง login ก่อน
// รับ token จาก header "Authorization: Bearer xxx" หรือ ?token=xxx (ใช้ตอนดาวน์โหลดไฟล์)
function login(req, res, next) {
  const token = (req.headers.authorization || '').replace('Bearer ', '') || req.query.token;
  try {
    req.user = jwt.verify(token, SECRET);
  } catch {
    return error(res, 401, 'กรุณาเข้าสู่ระบบ');
  }
  // ผู้ใช้ใหม่ต้องเปลี่ยนรหัสผ่านก่อน จึงจะใช้ API อื่นได้
  const allowed = ['/api/auth/me', '/api/auth/password'];
  if (req.user.must_change_password && !allowed.includes(req.originalUrl)) {
    return error(res, 403, 'กรุณาเปลี่ยนรหัสผ่านก่อนใช้งาน');
  }
  next();
}

// middleware: อนุญาตเฉพาะบทบาทที่กำหนด เช่น allow('admin')
function allow(...roles) {
  return (req, res, next) => {
    if (!roles.includes(req.user.role)) return error(res, 403, 'ไม่มีสิทธิ์ใช้งานส่วนนี้');
    next();
  };
}

module.exports = { createToken, login, allow };
  • createToken() ลงนามด้วย SECRET (ข้อ 6.6)
  • login คือ middleware ตรวจ token (ไม่มี/ผิด → 401) และถ้ายังต้องเปลี่ยนรหัสผ่าน → 403 (ข้อ 5.2.1)
  • allow('admin') ตรวจบทบาท (ข้อ 6.12)

// /api/auth — เข้าสู่ระบบ ข้อมูลส่วนตัว เปลี่ยนรหัสผ่าน
const router = require('express').Router();
const bcrypt = require('bcryptjs');
const { query } = require('../db');
const { ok, error } = require('../helpers');
const { createToken, login } = require('../auth');

// POST /api/auth/login  body: username, password
router.post('/login', async (req, res) => {
  const { username, password } = req.body;
  if (!username || !password) return error(res, 400, 'กรอกชื่อผู้ใช้และรหัสผ่าน');

  const rows = await query('SELECT * FROM users WHERE username = ?', [username]);
  const user = rows[0];
  if (!user || !(await bcrypt.compare(password, user.password))) {
    return error(res, 401, 'ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง');
  }
  delete user.password;
  ok(res, { token: createToken(user), user }, 'เข้าสู่ระบบสำเร็จ');
});

// GET /api/auth/me  ข้อมูลของคนที่ login อยู่
router.get('/me', login, async (req, res) => {
  const rows = await query(
    'SELECT id, username, full_name, email, department, role, must_change_password FROM users WHERE id = ?',
    [req.user.id],
  );
  if (rows.length === 0) return error(res, 404, 'ไม่พบผู้ใช้');
  ok(res, rows[0]);
});

// PUT /api/auth/me  แก้ข้อมูลส่วนตัว  body: full_name, email, department
router.put('/me', login, async (req, res) => {
  const { full_name, email, department } = req.body;
  if (!full_name) return error(res, 400, 'กรอกชื่อ-นามสกุล');
  if (email && !/^\S+@\S+\.\S+$/.test(email)) return error(res, 400, 'รูปแบบอีเมลไม่ถูกต้อง');

  await query('UPDATE users SET full_name = ?, email = ?, department = ? WHERE id = ?', [
    full_name, email || '', department || '', req.user.id,
  ]);
  ok(res, null, 'บันทึกข้อมูลส่วนตัวแล้ว');
});

// PUT /api/auth/password  เปลี่ยนรหัสผ่าน  body: old_password, new_password
router.put('/password', login, async (req, res) => {
  const { old_password, new_password } = req.body;
  if (!new_password || new_password.length < 8) {
    return error(res, 400, 'รหัสผ่านใหม่ต้องยาวอย่างน้อย 8 ตัวอักษร');
  }
  const rows = await query('SELECT * FROM users WHERE id = ?', [req.user.id]);
  const user = rows[0];
  if (!(await bcrypt.compare(old_password || '', user.password))) {
    return error(res, 400, 'รหัสผ่านเดิมไม่ถูกต้อง');
  }

  const hash = await bcrypt.hash(new_password, 10);
  await query('UPDATE users SET password = ?, must_change_password = 0 WHERE id = ?', [hash, user.id]);
  user.must_change_password = 0;
  ok(res, { token: createToken(user) }, 'เปลี่ยนรหัสผ่านแล้ว');
});

async function lockReason(period, userId) {
  if (!isOpen(period)) return 'อยู่นอกช่วงเวลาประเมิน แก้ไขไม่ได้';
  const rows = await query(
    "SELECT id FROM assignments WHERE period_id = ? AND evaluatee_id = ? AND status <> 'pending'",
    [period.id, userId],
  );
  if (rows.length > 0) return 'กรรมการประเมินแล้ว แก้ไขการประเมินตนเองไม่ได้';
  return null;
}

  // ใส่คะแนนและรายละเอียดลงในตัวชี้วัดแต่ละข้อ
  let done = 0;
  for (const item of indicators) {
    const row = scores.find((s) => s.indicator_id === item.id);
    item.my_score = row ? row.score : null;
    item.details = details.filter((d) => d.indicator_id === item.id);
    if (item.my_score !== null && item.details.length > 0) done++;
  }

  // ความเห็นกรรมการ แสดงเมื่อกรรมการยืนยันผลแล้ว
  const committees = await query(
    `SELECT u.full_name, a.committee_role, a.status,
       IF(a.status = 'confirmed', a.comment, NULL) AS comment
     FROM assignments a JOIN users u ON u.id = a.evaluator_id
     WHERE a.period_id = ? AND a.evaluatee_id = ?`,
    [req.params.id, req.user.id],
  );

  ok(res, {
    period: periods[0],
    can_edit: reason === null,
    lock_reason: reason,
    indicators,
    progress: indicators.length ? Math.round((done / indicators.length) * 100) : 0,

  });

    `SELECT a.*, u.full_name FROM assignments a JOIN users u ON u.id = a.evaluator_id
     WHERE a.period_id = ? AND a.evaluatee_id = ? ORDER BY a.committee_role`,

  );

  const isCommittee = committees.some((c) => c.evaluator_id === req.user.id);
  if (req.user.role !== 'admin' && !isOwner && !isCommittee) return error(res, 403, 'ไม่มีสิทธิ์ดูรายงานนี้');

  const users = await query('SELECT id, full_name, email, department FROM users WHERE id = ?', [userId]);
  const periods = await query('SELECT * FROM periods WHERE id = ?', [periodId]);
  if (users.length === 0 || periods.length === 0) return error(res, 404, 'ไม่พบข้อมูล');

  const indicators = await getIndicators(periodId);
  const selfScores = await query('SELECT * FROM self_scores WHERE evaluatee_id = ?', [userId]);
  for (const item of indicators) {
    const self = selfScores.find((s) => s.indicator_id === item.id);
    item.self_score = self ? self.score : null;
  }

  const confirmed = [];
  for (const c of committees) {
    c.scores = await query('SELECT indicator_id, score FROM scores WHERE assignment_id = ?', [c.id]);
    c.percent = percent(indicators, c.scores);

      c.scores = [];
      c.percent = null;
      c.comment = null;
    }

    ? Math.round((confirmed.reduce((sum, p) => sum + p, 0) / confirmed.length) * 100) / 100
    : null;

// /api/backup — สำรองและกู้คืนข้อมูลเป็นไฟล์ JSON (admin)
const router = require('express').Router();
const { pool, query } = require('../db');
const { ok, error } = require('../helpers');

// เรียงจากตารางแม่ → ตารางลูก
const TABLES = ['users', 'periods', 'topics', 'indicators', 'assignments', 'self_scores', 'self_details', 'scores'];

// GET /api/backup  ดาวน์โหลดข้อมูลทุกตารางเป็นไฟล์ JSON
router.get('/', async (req, res) => {
  const backup = { created_at: new Date().toISOString(), tables: {} };
  for (const table of TABLES) {
    backup.tables[table] = await query(`SELECT * FROM ${table}`);
  }
  res.setHeader('Content-Disposition', 'attachment; filename=backup.json');
  res.json(backup);
});

// POST /api/backup/restore  กู้คืนจากไฟล์ JSON  body: เนื้อหาไฟล์ backup.json
router.post('/restore', async (req, res) => {
  const tables = req.body.tables;
  if (!tables || !tables.users) return error(res, 400, 'ไฟล์สำรองไม่ถูกต้อง');

  const db = await pool.getConnection();
  try {
    await db.beginTransaction();
    await db.query('SET FOREIGN_KEY_CHECKS = 0');
    for (const table of TABLES) {
      await db.query(`DELETE FROM ${table}`);
      for (const row of tables[table] || []) {
        await db.query(`INSERT INTO ${table} SET ?`, [row]);
      }
    }
    await db.query('SET FOREIGN_KEY_CHECKS = 1');
    await db.commit();
  } catch (err) {
    await db.rollback();
    throw err;
  } finally {
    db.release();
  }
  ok(res, null, 'กู้คืนข้อมูลแล้ว');
});

9.3 คำถามที่กรรมการมักถาม และแนวตอบ

Back-end

  • JWT คืออะไร ทำไมใช้ — บัตรผ่านที่ server ลงนามไว้ ส่งมากับทุก request ใน Header ทำให้ server ไม่ต้องจำ session ถ้าแก้ข้อมูลข้างใน ลายเซ็นจะไม่ตรงและถูกปฏิเสธ
  • เก็บรหัสผ่านอย่างไร — เข้ารหัสทางเดียวด้วย bcrypt ไม่มีใครถอดกลับได้ ตอน login ใช้ bcrypt.compare
  • กัน SQL Injection อย่างไร — ใช้ ? ใน pool.query ให้ mysql2 ใส่ค่าให้ ไม่ต่อ string เอง
  • 401 กับ 403 ต่างกันอย่างไร — 401 ยังไม่ login หรือ token ผิด, 403 login แล้วแต่ไม่มีสิทธิ์
  • คิดคะแนนอย่างไร — แต่ละตัวชี้วัด (คะแนน ÷ คะแนนเต็ม) × น้ำหนัก รวมแล้วหารน้ำหนักรวม × 100
  • ทำไมยืนยันแล้วแก้ไม่ได้ — ตรวจ status = 'confirmed' ก่อนบันทึกทุกครั้ง ถ้ายืนยันแล้วตอบ 400
  • ทำไมแยก self_scores กับ self_details — คะแนนมีหนึ่งค่าต่อตัวชี้วัด แต่รายละเอียดมีได้หลายรายการ (ข้อ 5.2.3)

Front-end

  • Component คืออะไร — ชิ้นส่วนที่นำกลับมาใช้ซ้ำได้ เช่น ScoreSelect.vue ใช้ทั้งหน้าตนเองและหน้ากรรมการ
  • ทำ Responsive อย่างไร — ใช้ grid ของ Vuetify v-col cols="12" md="6" จอเล็กเต็มแถว จอใหญ่ครึ่งแถว
  • กันคนพิมพ์ URL เข้าหน้าที่ไม่มีสิทธิ์อย่างไร — router.beforeEach ตรวจบทบาท และหลังบ้านตรวจซ้ำอีกชั้น
  • ทำไมไม่ติด CORS — ใช้ proxy ของ Vite ส่งต่อ /api ไปหลังบ้าน (และเปิด cors() ไว้ด้วย)

การแก้ปัญหา

  • เจอปัญหาอะไรตอนทำ — เตรียมเรื่องจริง 1–2 เรื่องจากตอนซ้อม เช่น "Docker เปิดฐานข้อมูลไม่ทัน back-end จึงใส่ healthcheck และ depends_on: condition: service_healthy"
  • ถ้ามีเวลาเพิ่มจะพัฒนาอะไร — แจ้งเตือนทางอีเมล, กราฟสรุปผล, ลืมรหัสผ่าน

API ตอบ 401 ไม่ได้ส่ง token หรือ token หมดอายุ login ใหม่ ตรวจ Header Bearer <token> (มีเว้นวรรค)
API ตอบ 403 บทบาทไม่ตรง หรือยังไม่เปลี่ยนรหัสผ่าน ใช้บัญชีที่ถูกบทบาท / เปลี่ยนรหัสก่อน
หน้าเว็บขึ้น CORS error เรียก http://localhost:3000 ตรง ๆ ให้เรียก /api/... ผ่าน proxy และตรวจ API_URL ใน docker-compose
หน้าเว็บขาว Console ขึ้น Failed to resolve import ไฟล์ที่ import ยังไม่มี หรือสะกดผิด สร้างไฟล์หน้า (ดูขั้น 5.13) ตรวจตัวพิมพ์เล็กใหญ่
ภาษาไทยเป็น ??? ไฟล์ .sql ไม่ได้บันทึกเป็น UTF-8 หรือใช้ MySQL รุ่นเก่า ใน VS Code มุมขวาล่างต้องเป็น UTF-8, ใช้ image mysql:8.4 (ค่าเริ่มต้นเป็น utf8mb4) แล้ว docker compose down -v และ up ใหม่
อัปโหลดไฟล์ได้ 400 ชนิดไฟล์ไม่อยู่ในรายการที่อนุญาต หรือใหญ่เกิน ใช้ PDF/JPG/PNG ไม่เกินขนาดที่ตั้งใน upload.js และตรวจว่าชื่อช่องคือ file
อัปโหลดแล้วไฟล์หายหลัง restart ไม่ได้ map โฟลเดอร์ uploads โฟลเดอร์ ./backend ถูก mount อยู่แล้ว ห้ามลบโฟลเดอร์ uploads
npm create vite ถามคำถามเยอะ ใช้ npm เวอร์ชันใหม่ เลือก Vue → JavaScript คำถามอื่น (rolldown, ติดตั้งและเปิดเลยไหม) ตอบ No
กด Export PDF แล้วไม่ได้ไฟล์ Console ขึ้น unsupported color function ติดตั้ง Vuetify 4 (พิมพ์ npm install vuetify โดยไม่ใส่เวอร์ชัน) ในโฟลเดอร์ frontend พิมพ์ npm install vuetify@3 html2pdf.js@0.10 แล้วปิดเปิด npm run dev ใหม่ (ถ้ายังไม่หาย ลบโฟลเดอร์ node_modules/.vite)
หน้าเว็บเปิดมาพื้นดำ ปุ่มเป็นตัวพิมพ์เล็ก ได้ Vuetify 4 (ใช้ธีมตาม Windows) แทน Vuetify 3 ติดตั้งใหม่ด้วย npm install vuetify@3 ตามข้อ 5.1
login ด้วยรหัสในคู่มือแล้วได้ 401 ทั้งที่พิมพ์ถูก ฐานข้อมูลมีผู้ใช้เก่าค้างจากการรันครั้งก่อน (seed ใช้ INSERT IGNORE ไม่เขียนทับ) หรือเคยเปลี่ยนรหัสไปแล้ว ลองรหัสที่เปลี่ยนไว้ (เช่น newpass123) หรือรีเซ็ตแบบ "เริ่มใหม่หมดแบบสะอาด" ด้านล่าง
เปิดเว็บแล้วเห็นหน้าตาของงานเวอร์ชันอื่น เคยรันโปรเจกต์อื่นที่ใช้พอร์ตเดียวกันค้างไว้ ไปที่โฟลเดอร์โปรเจกต์เก่าแล้ว docker compose down ก่อน หรือดูใน Docker Desktop ว่า container ไหนเปิดอยู่
ผู้รับการประเมินกดบันทึกคะแนนไม่ได้ ขึ้น "กรรมการประเมินแล้ว..." ถูกต้องตามระบบ กรรมการบันทึกร่างหรือยืนยันผลไปแล้ว ถ้ากำลังซ้อม ให้รีเซ็ตฐานข้อมูลแล้วทำตามลำดับ ผู้รับกรอกให้เสร็จก่อนกรรมการเริ่ม
ผู้รับการประเมินไม่เห็นคะแนนกรรมการ แต่ admin เห็น ถูกต้องตามระบบ ผู้รับเห็นเฉพาะผลที่กรรมการกด "ยืนยันและส่งผล" แล้ว ให้กรรมการกรอกคะแนนครบ เขียนความเห็น แนบลายเซ็น แล้วกดยืนยัน
git push ถามรหัสผ่านแล้วไม่ผ่าน GitLab ต้องใช้ Access Token GitLab → Preferences → Access Tokens สร้างแล้วใช้แทนรหัสผ่าน
