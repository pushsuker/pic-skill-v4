## 8.1 Unit Test คิดคะแนน (ข้อ 7.5)

ใช้ test runner ที่มากับ Node 24 ไม่ต้องติดตั้งเพิ่ม

ไฟล์ `backend/tests/score.test.js`

```js
// ทดสอบฟังก์ชันคำนวณคะแนน (ข้อ 7.5)  รัน: npm test
const test = require('node:test');
const assert = require('node:assert');
const { percent, validScore } = require('../helpers');

const indicators = [
  { id: 1, score_type: 'scale', weight: 60 },
  { id: 2, score_type: 'yesno', weight: 40 },
];

test('คะแนนเต็มทุกข้อ ได้ 100%', () => {
  const scores = [{ indicator_id: 1, score: 4 }, { indicator_id: 2, score: 1 }];
  assert.strictEqual(percent(indicators, scores), 100);
});

test('ถ่วงน้ำหนัก: ระดับ 2 จาก 4 (60) + ไม่มี (40) = 30%', () => {
  const scores = [{ indicator_id: 1, score: 2 }, { indicator_id: 2, score: 0 }];
  assert.strictEqual(percent(indicators, scores), 30);
});

test('ให้คะแนนไม่ครบ ได้ null', () => {
  assert.strictEqual(percent(indicators, [{ indicator_id: 1, score: 4 }]), null);
});

test('ตรวจชนิดคะแนน', () => {
  assert.strictEqual(validScore(indicators[0], 5), false);
  assert.strictEqual(validScore(indicators[1], 1), true);
});
```

```bash
docker compose exec backend npm test
# หรือรันตรงในเครื่อง
cd backend
npm test
```

ผลที่ต้องได้: `pass 4` `fail 0`

## 8.2 ทดสอบ API อัตโนมัติ (ข้อ 7.1–7.3, 7.6)

ต้องเปิด back-end ไว้ก่อน

ไฟล์ `backend/tests/api.test.js`

```js
// ทดสอบ API จริง (ข้อ 7.1-7.3, 7.6)  ต้องเปิด backend ไว้ก่อน
// รัน: docker compose exec backend npm run test:api
const test = require('node:test');
const assert = require('node:assert');

const URL = 'http://localhost:' + (process.env.PORT || 3000) + '/api';
let token = '';

// ฟังก์ชันเรียก API คืน { status, body }
async function call(path, method = 'GET', body) {
  const res = await fetch(URL + path, {
    method,
    headers: { 'Content-Type': 'application/json', Authorization: 'Bearer ' + token },
    body: body ? JSON.stringify(body) : undefined,
  });
  return { status: res.status, body: await res.json() };
}

test('7.1 Login รหัสผิด ได้ 401', async () => {
  const r = await call('/auth/login', 'POST', { username: 'admin', password: 'wrong' });
  assert.strictEqual(r.status, 401);
});

test('7.1 Login รหัสถูก ได้ token', async () => {
  const r = await call('/auth/login', 'POST', { username: 'admin', password: 'admin1234' });
  assert.strictEqual(r.status, 200);
  token = r.body.data.token;
});

const username = 'test' + Date.now();
let newId;

test('7.4 Validate: อีเมลผิดรูปแบบ ได้ 400', async () => {
  const r = await call('/users', 'POST', {
    username, password: 'test12345', full_name: 'ทดสอบ', role: 'evaluatee', email: 'abc',
  });
  assert.strictEqual(r.status, 400);
});

test('7.2 Insert: POST เพิ่มผู้ใช้', async () => {
  const r = await call('/users', 'POST', {
    username, password: 'test12345', full_name: 'ทดสอบ', role: 'evaluatee', email: 'a@b.com',
  });
  assert.strictEqual(r.status, 200);
  newId = r.body.data.id;
});

test('7.3 Update: PUT แก้ชื่อ แล้ว GET ตรวจผล', async () => {
  await call('/users/' + newId, 'PUT', { full_name: 'ชื่อใหม่', role: 'evaluatee' });
  const r = await call('/users/' + newId);
  assert.strictEqual(r.body.data.full_name, 'ชื่อใหม่');
});

test('DELETE ลบผู้ใช้ทดสอบ', async () => {
  const r = await call('/users/' + newId, 'DELETE');
  assert.strictEqual(r.status, 200);
});

test('4.4 ไม่มี token ได้ 401 / ไม่มี API ได้ 404', async () => {
  token = '';
  assert.strictEqual((await call('/users')).status, 401);
  assert.strictEqual((await call('/nothing')).status, 404);
});
```

```bash
docker compose exec backend npm run test:api
```

ผลที่ต้องได้: `pass 7` `fail 0`

## 8.3 ทดสอบด้วย Thunder Client (ให้กรรมการดูสด)

ติดตั้ง Extension `rangav.vscode-thunder-client` แล้วสร้าง Collection ชื่อ `evaluation-2569`

| ข้อ | Method + URL | Body / Header | ผลที่ต้องได้ |
|---|---|---|---|
| 7.1 Login ถูก | `POST /api/auth/login` | `{"username":"admin","password":"admin1234"}` | 200 + `data.token` |
| 7.1 Login ผิด | `POST /api/auth/login` | รหัสผิด | 401 |
| 7.2 ไม่มี token | `GET /api/users` | ไม่ใส่ Header | 401 |
| 7.2 สิทธิ์ไม่ถึง | `GET /api/users` | token ของ emp1 (ที่เปลี่ยนรหัสแล้ว) | 403 ไม่มีสิทธิ์ใช้งานส่วนนี้ |
| 7.3 CRUD | `POST/PUT/DELETE /api/periods` | token admin | 200 / `PUT` หรือ `DELETE /api/periods/999` ได้ 404 |
| 7.4 Validation | `POST /api/users` | ไม่ใส่ username | 400 กรอกชื่อผู้ใช้ (ไม่เกิน 50 ตัว) |
| 7.5 คิดคะแนน | `GET /api/reports/result/1/2` | token admin | `data.committees[].percent` ของแต่ละกรรมการ และ `data.total` (เฉลี่ยของกรรมการที่ยืนยันแล้ว) ตรงกับคิดมือ |
| 7.6 อัปโหลด | `POST /api/self/details` | token emp1, Body แบบ Form: `indicator_id`=1, `detail`=ทดสอบ, `file`=ไฟล์ .exe | 400 รับเฉพาะไฟล์ PDF, PNG, JPG |

> ตัวอย่างคิดมือข้อ 7.5 จากข้อมูล seed: แผนการสอน (สเกล น้ำหนัก 60) ได้ 3 + อบรม (มี/ไม่มี น้ำหนัก 40) ได้ 1 → (3/4 × 60 + 1/1 × 40) / 100 × 100 = **85%**

> ทุก request ที่ต้อง login ให้ใส่ Header `Authorization` = `Bearer <token>` หรือใช้แท็บ Auth → Bearer

URL เต็มคือ `http://localhost:3000/api/...` รายละเอียดทุกเส้นดูใน `docs/API.md` ของเฉลย

> ยิง `http://localhost:3000/api` เฉย ๆ จะได้ 404 "ไม่พบ API นี้" ต้องต่อชื่อ API เสมอ และ login ต้องเป็น **POST** (Postman ตั้งค่าเริ่มต้นเป็น GET)

### ฝึกยิงทีละ request ด้วยไฟล์ `.http` (VS Code)

เฉลยมีไฟล์ `docs/api-practice.http` รวม 29 request ไล่ตั้งแต่ login, CRUD ผู้ใช้, รอบ, รายงาน ไปจนถึงฝั่งผู้รับ (emp1) และกรรมการ (eva1) แต่ละข้อเขียนผลที่ต้องได้ไว้ในชื่อ

1. ติดตั้ง Extension **REST Client** (`humao.rest-client`)
2. คัดลอก `api-practice.http` จากเฉลยมาไว้ที่ `docs/` ของทีม แล้วเปิดใน VS Code
3. กด **Send Request** ที่อยู่เหนือข้อ 1 (Login admin) ก่อนเสมอ token จะถูกเก็บในตัวแปร `{{token}}` ให้ข้อถัดไปใช้เอง ผลจะขึ้นแท็บทางขวา
4. กดทีละข้อตามลำดับ ดูว่า status ตรงกับที่เขียนในชื่อข้อ
5. ข้อ 21 (แนบไฟล์) ต้องวางไฟล์ `sample.pdf` ไว้ในโฟลเดอร์เดียวกับไฟล์ `.http` ก่อน

> ข้อ 16–17 และ 22–23 (เปลี่ยนรหัสครั้งแรก) ยิงได้ครั้งเดียว ถ้าเคยเปลี่ยนแล้วให้ข้ามไปข้อ 18 / 24 ถ้าอยากเริ่มใหม่ทั้งหมดให้ `docker compose down -v` แล้ว `docker compose up -d`

ซ้อมเขียนเอง: ลองลบ body ของบางข้อทิ้งแล้วให้นักเรียนเขียนกลับจาก `docs/API.md`

### ทดสอบอัตโนมัติด้วย Postman (Import Collection)

เฉลยมีไฟล์ `docs/evaluation-2569-ทดสอบAPI.postman_collection.json` รวม **60 request / 83 การตรวจ** ครอบคลุมทุกบทบาท ระบบจะสร้างผู้ใช้ รอบ หัวข้อ ตัวชี้วัด และการมอบหมายสำหรับทดสอบเอง แล้วลบทิ้งตอนจบ **รันซ้ำได้หลายครั้งโดยไม่กระทบข้อมูลจริง**

วิธี Import
1. เปิด backend ไว้ก่อน (`docker compose up -d`)
2. เปิด Postman → กด **Import** (มุมซ้ายบน) → ลากไฟล์ `.postman_collection.json` วางลงไป → กด **Import**
3. Collection ชื่อ "evaluation-2569 ทดสอบ API อัตโนมัติ" จะขึ้นที่แถบซ้าย มี 8 โฟลเดอร์ (ตั้งต้น, Login, ผู้ใช้, รอบ, ผู้รับ, กรรมการ, รายงาน, ลบข้อมูลทดสอบ)

วิธีรันทั้งชุด
1. คลิกขวาที่ชื่อ Collection → **Run collection** (หรือกดปุ่ม Run)
2. ไม่ต้องเปลี่ยนค่าอะไร กด **Run evaluation-2569...**
3. ผลที่ต้องได้: ทุกข้อขึ้น **PASS** สีเขียว ด้านบนสรุป Passed 83 / Failed 0

ถ้าอยากยิงทีละข้อ ให้กด request ตามลำดับเลขข้างหน้า (00, 01, 02, ...) เพราะข้อหลังใช้ token และ id จากข้อก่อน ดูผลการตรวจได้ที่แท็บ **Test Results** ใต้ response

> ถ้ามีข้อ FAIL ให้กดข้อนั้นดู Response ว่า backend ตอบอะไร เทียบกับชื่อข้อที่บอกผลที่ต้องได้ แล้วแก้โค้ดใน `routes/` ที่เกี่ยวข้อง
> ถ้าเปลี่ยนพอร์ต backend ให้แก้ตัวแปร `base` ที่แท็บ **Variables** ของ Collection

ใช้ทั้งสองไฟล์โชว์ข้อ 7.1–7.6 ตอนนำเสนอได้ทันที

## 8.6 Deploy ขึ้นเครื่อง Server (ข้อ 7.9)

บนเครื่อง Server ที่ติดตั้ง Docker แล้ว

```bash
git clone https://gitlab.com/<ชื่อทีม>/evaluation-2569.git
cd evaluation-2569
docker compose up -d
docker compose ps          # ทุกตัวต้อง Up / healthy
```

ดู IP ของ Server

```bash
ip a          # Linux
ipconfig      # Windows
```

เปิดจากเครื่องอื่นด้วย `http://<IP>:5173`

ถ้าเปิดไม่ได้ ให้เปิดพอร์ต Firewall

```bash
# Linux (ufw)
sudo ufw allow 5173
sudo ufw allow 3000
```

```powershell
# Windows (PowerShell แบบ Administrator)
New-NetFirewallRule -DisplayName "evaluation" -Direction Inbound -Protocol TCP -LocalPort 5173,3000 -Action Allow
```

อัปเดตงานใหม่บน Server

```bash
git pull
docker compose restart backend frontend
```
