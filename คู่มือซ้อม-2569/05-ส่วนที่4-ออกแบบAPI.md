# 05 ส่วนที่ 4 การออกแบบ RESTful API — 5 คะแนน

ผู้รับผิดชอบ: **คนที่ 3** เขียนเอกสาร `docs/API.md` (คัดลอกจากเฉลยแล้วปรับได้) · **คนที่ 1** ทำ API ให้ตรงเอกสาร

## 1. หลัก RESTful (ข้อ 4.1–4.2)

| Method | ใช้ทำ | ตัวอย่าง |
|---|---|---|
| GET | อ่านข้อมูล | `GET /api/users`, `GET /api/users/5` |
| POST | เพิ่มข้อมูลใหม่ | `POST /api/users` |
| PUT | แก้ไขข้อมูล | `PUT /api/users/5` |
| DELETE | ลบข้อมูล | `DELETE /api/users/5` |

ชื่อ Endpoint เป็น **คำนามพหูพจน์** (`/users`, `/periods`, `/indicators`) และใช้ `/:id` ระบุตัวที่ต้องการ ไม่ใส่คำกริยาใน URL (ยกเว้นงานพิเศษเช่น `/login`, `/confirm`, `/reset-password`)

## 2. รูปแบบ Response เดียวกันทุก API (ข้อ 4.3, 6.8)

```json
{ "status": "success", "message": "เพิ่มผู้ใช้แล้ว", "data": { "id": 6 } }
```

```json
{ "status": "error", "message": "ไม่พบผู้ใช้", "data": null }
```

| Status Code | ใช้เมื่อ (ข้อ 4.4) |
|---|---|
| 200 OK | สำเร็จ |
| 400 Bad Request | ข้อมูลไม่ครบ / ผิดรูปแบบ / ซ้ำ |
| 401 Unauthorized | ไม่มี token หรือ token ผิด / รหัสผ่านผิด |
| 403 Forbidden | login แล้วแต่ไม่มีสิทธิ์ (เช่น ผู้รับเรียก API ของ admin) |
| 404 Not Found | ไม่พบข้อมูล หรือไม่มี API นี้ |
| 500 Internal Server Error | โค้ดพัง / ฐานข้อมูลมีปัญหา |

## 3. ความปลอดภัย (ข้อ 4.5, 6.12)

1. Login สำเร็จ → server สร้าง **JWT** ที่ลงนามด้วย `JWT_SECRET` อายุ 8 ชั่วโมง
2. หน้าเว็บเก็บ token ใน `localStorage` และแนบทุกครั้ง `Authorization: Bearer <token>`
3. middleware `login` ตรวจ token → ไม่ผ่าน = 401
4. middleware `allow('admin')` ตรวจบทบาท → ไม่ตรง = 403
5. รหัสผ่านเก็บแบบ **bcrypt hash** ไม่เก็บตัวจริง
6. SQL ใช้ `?` (prepared statement) ป้องกัน SQL Injection

## 4. รายการ API ทั้งหมด

ดูเอกสารเต็มในไฟล์ `docs/API.md` ของเฉลย (มีตารางทุก Endpoint พร้อม parameter และตัวอย่าง 6.1–6.4 แบบละเอียด) สรุปกลุ่มได้ดังนี้

| กลุ่ม | Path หลัก | สิทธิ์ |
|---|---|---|
| เข้าสู่ระบบ / ข้อมูลส่วนตัว | `/api/auth` | ทุกคน |
| ผู้ใช้ | `/api/users` | admin |
| รอบ หัวข้อ ตัวชี้วัด | `/api/periods`, `/api/topics`, `/api/indicators` | admin |
| มอบหมายกรรมการ | `/api/assignments` | admin |
| ประเมินตนเอง | `/api/self` | evaluatee |
| ให้คะแนน | `/api/evaluate` | evaluator |
| รายงาน | `/api/reports` | ตามสิทธิ์ |
| ไฟล์ | `/api/files` | login |
| สำรองข้อมูล | `/api/backup` | admin |

ในเอกสาร **ต้องระบุ parameter** ว่ามาจากไหน (ข้อ 6.10)
- **path** เช่น `/users/:id` → `req.params.id`
- **query** เช่น `/users?role=evaluator` → `req.query.role`
- **body** (JSON) → `req.body.full_name`
- **form-data** (อัปโหลดไฟล์) → `req.file`
