## 9.3 คำถามที่กรรมการมักถาม และแนวตอบ

**Back-end**

- *JWT คืออะไร ทำไมใช้* — บัตรผ่านที่ server ลงนามไว้ ส่งมากับทุก request ใน Header ทำให้ server ไม่ต้องจำ session ถ้าแก้ข้อมูลข้างใน ลายเซ็นจะไม่ตรงและถูกปฏิเสธ
- *เก็บรหัสผ่านอย่างไร* — เข้ารหัสทางเดียวด้วย bcrypt ไม่มีใครถอดกลับได้ ตอน login ใช้ `bcrypt.compare`
- *กัน SQL Injection อย่างไร* — ใช้ `?` ใน `pool.query` ให้ mysql2 ใส่ค่าให้ ไม่ต่อ string เอง
- *401 กับ 403 ต่างกันอย่างไร* — 401 ยังไม่ login หรือ token ผิด, 403 login แล้วแต่ไม่มีสิทธิ์
- *คิดคะแนนอย่างไร* — แต่ละตัวชี้วัด (คะแนน ÷ คะแนนเต็ม) × น้ำหนัก รวมแล้วหารน้ำหนักรวม × 100
- *ทำไมยืนยันแล้วแก้ไม่ได้* — ตรวจ `status = 'confirmed'` ก่อนบันทึกทุกครั้ง ถ้ายืนยันแล้วตอบ 400
- *ทำไมแยก self_scores กับ self_details* — คะแนนมีหนึ่งค่าต่อตัวชี้วัด แต่รายละเอียดมีได้หลายรายการ (ข้อ 5.2.3)

**Front-end**

- *Component คืออะไร* — ชิ้นส่วนที่นำกลับมาใช้ซ้ำได้ เช่น `ScoreSelect.vue` ใช้ทั้งหน้าตนเองและหน้ากรรมการ
- *ทำ Responsive อย่างไร* — ใช้ grid ของ Vuetify `v-col cols="12" md="6"` จอเล็กเต็มแถว จอใหญ่ครึ่งแถว
- *กันคนพิมพ์ URL เข้าหน้าที่ไม่มีสิทธิ์อย่างไร* — `router.beforeEach` ตรวจบทบาท และหลังบ้านตรวจซ้ำอีกชั้น
- *ทำไมไม่ติด CORS* — ใช้ proxy ของ Vite ส่งต่อ `/api` ไปหลังบ้าน (และเปิด `cors()` ไว้ด้วย)

**การแก้ปัญหา**

- *เจอปัญหาอะไรตอนทำ* — เตรียมเรื่องจริง 1–2 เรื่องจากตอนซ้อม เช่น "Docker เปิดฐานข้อมูลไม่ทัน back-end จึงใส่ `healthcheck` และ `depends_on: condition: service_healthy`"
- *ถ้ามีเวลาเพิ่มจะพัฒนาอะไร* — แจ้งเตือนทางอีเมล, กราฟสรุปผล, ลืมรหัสผ่าน
