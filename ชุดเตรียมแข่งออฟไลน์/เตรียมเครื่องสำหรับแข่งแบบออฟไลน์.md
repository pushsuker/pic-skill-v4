# เตรียมเครื่องสำหรับแข่งแบบออฟไลน์

ใช้เมื่อสนามแข่งไม่มีอินเทอร์เน็ต (หรือเน็ตช้าจนเชื่อไม่ได้) ตัวระบบที่เขียนไม่ได้เรียกอะไรจากเน็ตเลย ปัญหาอยู่ที่ **การติดตั้ง** ซึ่งต้องโหลดของจากเน็ต ชุดนี้ให้ทุกอย่างที่ต้องโหลด ถูกโหลดไว้ก่อนตั้งแต่ตอนยังมีเน็ต

> ทำ **บนเครื่องที่จะใช้แข่งจริง** และทำ **ก่อนวันแข่ง** ตอนที่ยังมีอินเทอร์เน็ต ใช้เวลาประมาณ 10–15 นาทีต่อเครื่อง

## ทำไมถ้าไม่เตรียมจะพัง

| จุด | เกิดอะไรขึ้นตอนออฟไลน์ |
|---|---|
| Docker image (mysql, phpmyadmin, node) | ถ้าเครื่องไม่เคยดึงไว้ `docker compose up` จะ error ทันที |
| `npm init` `npm install` `npm create vite` (คู่มือขั้น 1 และ 5) | โหลดแพ็กเกจไม่ได้ เริ่มโปรเจกต์ไม่ได้เลย |
| `docker-compose.yml` ของคู่มือหลัก | backend และ frontend รัน `npm install` ทุกครั้งที่เปิด และเก็บ node_modules ใน volume ชั่วคราว ถ้าเคย `docker compose down` แล้วเปิดใหม่ volume จะว่าง **ระบบค้างที่ npm install ไม่ขึ้น** (ทดสอบแล้ว) |
| Draw.io แบบเว็บ, Extension ของ VS Code | ต้องโหลดจากเน็ต |

## ในชุดนี้มีอะไร

```
ชุดเตรียมแข่งออฟไลน์/
├─ เตรียมเครื่องสำหรับแข่งแบบออฟไลน์.html   ← คู่มือนี้
└─ evaluation/                            ← โฟลเดอร์งานของทีม (ก๊อปไปใช้ทั้งโฟลเดอร์)
   ├─ docker-compose.yml        ← รุ่นออฟไลน์ (ต่างจากคู่มือหลัก 2 จุด ดูด้านล่าง)
   ├─ .gitignore
   ├─ เตรียมเครื่อง.ps1          ← รันครั้งเดียวตอนมีเน็ต
   ├─ แผนสำรอง-backend.ps1       ← ใช้เมื่อ container มีปัญหา
   ├─ แผนสำรอง-frontend.ps1
   ├─ backend/   package.json  package-lock.json  node_modules/  routes/  tests/
   ├─ frontend/  package.json  package-lock.json  node_modules/  src/pages/  src/components/
   ├─ docs/
   └─ design/
```

- แพ็กเกจติดตั้งไว้แล้วทั้งสองฝั่ง เวอร์ชันตรงกับเฉลย (Vuetify 3.13, Vite 6, vue-router 4, html2pdf.js 0.10, Express 5) ขนาดรวมประมาณ 160 MB
- ยังไม่มีโค้ดของระบบ นักเรียนเขียนเองตามคู่มือหลัก

`docker-compose.yml` รุ่นออฟไลน์ต่างจากคู่มือหลัก 2 จุด

```yaml
# 1) คำสั่งตอนเริ่ม: ใช้แพ็กเกจที่มีอยู่ก่อน ไม่เช็กช่องโหว่ออนไลน์
command: sh -c "npm install --prefer-offline --no-audit --no-fund && npm run seed && npm run dev"
# 2) node_modules เก็บใน named volume ไม่หายเมื่อ docker compose down
volumes:
  - ./backend:/app
  - backend_modules:/app/node_modules
```

## ขั้นที่ 1 ติดตั้งโปรแกรม (ตอนมีเน็ต)

| โปรแกรม | หมายเหตุ |
|---|---|
| Docker Desktop | เปิดให้ไอคอนเป็นสีเขียว |
| Node.js 24 | ใช้กับแผนสำรอง และรัน `npm test` บนเครื่อง |
| VS Code | ติดตั้ง Extension ให้ครบตอนนี้: Vue (Official), Thunder Client, REST Client |
| Draw.io Desktop | ต้องเป็นตัวติดตั้ง (drawio-x.x.x-windows-installer.exe) ไม่ใช่เว็บ |
| Git | ถ้าสนามไม่มี GitLab ในวง LAN ให้ใช้ git ในเครื่องเก็บประวัติ commit ไปก่อน |
| Postman (ถ้าใช้) | ต้อง login ตอนมีเน็ตครั้งแรก หรือใช้ Thunder Client / REST Client แทน |

## ขั้นที่ 2 ก๊อปชุดลงเครื่องแล้วรันสคริปต์เตรียมเครื่อง (ตอนมีเน็ต)

1. ก๊อปโฟลเดอร์ `evaluation` ไปไว้ในเครื่อง เช่น `D:\evaluation` (ชื่อโฟลเดอร์ต้องเป็น `evaluation` ตลอด เพราะ Docker ตั้งชื่อ volume ตามชื่อโฟลเดอร์)
2. เปิด Docker Desktop ให้ไอคอนเขียว
3. เปิด PowerShell ที่โฟลเดอร์ `evaluation` แล้วพิมพ์

```powershell
powershell -ExecutionPolicy Bypass -File .\เตรียมเครื่อง.ps1
```

สคริปต์ทำ 4 อย่าง

1. ตรวจว่า Docker Desktop เปิดอยู่
2. ดึง image `mysql:8.4` `phpmyadmin:5` `node:24-alpine`
3. ติดตั้งแพ็กเกจลงใน volume ของ container ทั้ง backend และ frontend (เป็นรุ่น Linux แยกจาก node_modules ในโฟลเดอร์ ซึ่งเป็นรุ่น Windows)
4. สร้างฐานข้อมูลไว้ล่วงหน้า รอจน MySQL พร้อม (healthy) แล้วค่อยหยุด

ต้องจบด้วยข้อความสีเขียว **"เตรียมเครื่องเสร็จแล้ว ตัดอินเทอร์เน็ตได้เลย"**

> ห้ามปิดหน้าต่างระหว่างขั้น 4 ถ้า MySQL ถูกหยุดตอนกำลังสร้างฐานข้อมูลครั้งแรก ไฟล์ฐานข้อมูลจะเสีย (เจอจริงตอนทดสอบ) ถ้าเผลอปิด ให้ลบ volume แล้วรันสคริปต์ใหม่: `docker compose down` → `docker volume rm evaluation_db_data` → รันสคริปต์อีกครั้ง

## ขั้นที่ 3 ทดสอบว่าออฟไลน์ได้จริง (ทำก่อนวันแข่ง)

1. ปิด Wi-Fi / ถอดสาย LAN
2. คัดลอกโค้ดเฉลย (`project/backend` ยกเว้น node_modules และ `project/frontend/src`, `index.html`, `vite.config.js`) ลงในชุดชั่วคราวเพื่อทดลอง หรือข้ามข้อนี้ถ้าจะลองหลังเขียนเสร็จ
3. ที่โฟลเดอร์ `evaluation`

```powershell
docker compose up -d
docker compose logs backend frontend
```

- [ ] log ขึ้น `up to date` (ไม่ได้โหลดอะไร) ตามด้วย `API พร้อมที่ http://localhost:3000` และ `VITE ... ready`
- [ ] เปิด http://localhost:8080 phpMyAdmin ได้ และ http://localhost:5173 เห็นหน้า Login
- [ ] `docker compose down` แล้ว `docker compose up -d` อีกรอบ ยังขึ้นได้เหมือนเดิม
- [ ] ถ้าลองข้อ 2 ไว้ ลบโค้ดทดลองทิ้งก่อนแข่ง (เหลือแค่ package.json, package-lock.json, node_modules)

ผลทดสอบของผู้จัดทำ: ปิดการเข้าถึง npm registry ทั้งหมด แล้ว `down` → `up` ระบบขึ้นครบ login ผ่านหน้าเว็บได้ ส่วน `docker-compose.yml` ของคู่มือหลักภายใต้เงื่อนไขเดียวกันค้างอยู่ที่ `npm install` ไม่ขึ้นเลย

## ตอนแข่ง: ทำตามคู่มือหลัก แต่ข้ามคำสั่งติดตั้ง

ทำงานในโฟลเดอร์ `evaluation` ของชุดนี้ แล้วทำตามคู่มือหลักทุกขั้น **ยกเว้น** ตารางนี้

| คู่มือหลัก | ทำอย่างไรในชุดออฟไลน์ |
|---|---|
| 1.1 `mkdir` `npm init` `npm install ...` | **ข้าม** โฟลเดอร์และแพ็กเกจมีครบแล้ว |
| 1.2 แก้ `backend/package.json` | **ข้าม** มีครบแล้ว |
| 1.3 `docker-compose.yml` | **ห้ามเขียนทับ** ใช้รุ่นออฟไลน์ในชุดนี้ |
| 1.4 `.gitignore` | มีแล้ว |
| 5.1 `npm create vite` `npm install` `rm ...` | **ข้าม** ทำแค่ "สร้างหน้าชั่วคราวทั้ง 14 หน้า" (โฟลเดอร์ `src/pages` มีให้แล้ว) |
| 5.1 ตรวจ `frontend/package.json` | **ไม่ต้องแก้** |
| ไฟล์โค้ดทุกไฟล์ที่เหลือ | เขียนตามคู่มือหลักตามปกติ |

คำสั่งที่ใช้ได้ / ห้ามใช้ระหว่างแข่ง

| ใช้ได้ | ห้ามใช้ (ต้องใช้เน็ต หรือลบของที่เตรียมไว้) |
|---|---|
| `docker compose up -d` | `docker compose down -v` (ลบ node_modules ที่เตรียมไว้ทิ้ง) |
| `docker compose stop` / `start` / `restart` | `npm install ชื่อแพ็กเกจใหม่` |
| `docker compose down` (ไม่มี -v) | `npm create vite` |
| `docker compose logs -f backend` | `docker compose pull` |
| `docker compose exec backend npm test` | ลบโฟลเดอร์ `node_modules` |

> อยากล้างฐานข้อมูลระหว่างซ้อม (แทน `down -v`): `docker compose down` → `docker volume rm evaluation_db_data` → `docker compose up -d` จะล้างแค่ฐานข้อมูล แพ็กเกจยังอยู่

## แผนสำรอง: container ค้างที่ npm install

ถ้า `docker compose logs backend` ค้างอยู่ที่ `npm install` นาน (เช่น volume ถูกลบไป) ให้รัน backend/frontend บนเครื่องโดยตรง ใช้ node_modules รุ่น Windows ที่อยู่ในโฟลเดอร์ ฐานข้อมูลยังอยู่ใน Docker เหมือนเดิม

```powershell
docker compose stop backend frontend
docker compose up -d db phpmyadmin
# หน้าต่าง PowerShell ที่ 1
powershell -ExecutionPolicy Bypass -File .\แผนสำรอง-backend.ps1
# หน้าต่าง PowerShell ที่ 2
powershell -ExecutionPolicy Bypass -File .\แผนสำรอง-frontend.ps1
```

เปิด http://localhost:5173 ใช้งานได้ตามปกติ (ทดสอบแล้ว: seed, เปิด API, login ผ่านหน้าเว็บได้โดยไม่ใช้เน็ต) แก้ไฟล์แล้วรีโหลดเองเหมือนเดิม
